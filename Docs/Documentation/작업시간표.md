# 2주 작업 시간표

2026-11-05 작성 · 근거: `Docs/Documentation/기능명세서.md`

## 전제

| 항목 | 내용 |
| --- | --- |
| 기간 | 2026-11-09(월) ~ 2026-11-20(금), 평일 10일 |
| 인원 | 1명 |
| 하루 작업 | 오전 3시간 + 오후 3시간 (사정에 맞게 조정) |
| 목표 | **하루 루프 한 바퀴가 돌아가는 최소 버전** (낮 채집 → 저녁 가공 → 밤 판매 → 다음 날) |
| 범위 | 명세서 P1 기능 9개. P2·P3는 이번 2주에 넣지 않는다. |

> 처음 개발할 때는 기능 하나에 예상보다 시간이 두세 배 더 걸리는 경우가 많다. 그래서 금요일 오후는 **밀린 작업을 따라잡는 시간**으로 비워 두었다.

## 날짜별 상세

각 날에 **완료 기준**(이게 되면 끝)과 **생각해볼 질문**을 적었다. 질문은 코딩을 시작하기 전에 스스로 답을 적어 보자.

### 1주차 — 낮(숲) 만들기

#### 11/09 월 · 준비 + 이동 마무리
- **오전**: 명세서 "기획에서 정할 것" 가운데 이번 2주에 꼭 필요한 것만 정한다.
    - 낮 제한은 체력인가, 시간인가? (F-06)
    - 점프를 넣을 것인가? (`PlayerMove.cs`)
    - 가방 기본 용량은 몇 칸인가? (임시 숫자도 괜찮다)
- **오후**: `PlayerMove.cs` 정리
    - 좌우 이동, 방향 전환, 애니메이션이 Play 모드에서 에러 없이 동작하는지 확인
    - 점프를 넣기로 했다면 입력 방식을 이동과 맞추고, 빼기로 했다면 관련 코드를 정리
- **완료 기준**: Console에 에러 없이 좌우로 걷고, 멈추면 대기 애니메이션이 나온다.
- **생각해볼 질문**: 1D Axis 바인딩은 어떤 타입의 값을 돌려줄까?

#### 11/10 화 · 상호작용 (F-02)
- **오전**: 설계. 종이에 그려 본다.
    - 플레이어는 "근처에 무엇이 있는지"를 어떻게 알까?
    - 채집물·가공대·손님이 모두 같은 키에 반응하려면 무엇이 공통이어야 할까?
- **오후**: 상호작용 키를 누르면 근처 대상의 이름이 Console에 찍히도록 만든다.
- **완료 기준**: 테스트용 오브젝트 2종류에 다가가 키를 누르면 각자 다른 로그가 나온다.

#### 11/11 수 · 채집 (F-03)
- **오전**: 아이템 정보를 어디에 둘지 정한다(이름, 종류, 가격 등).
    - 산초 하나가 가방·가공·판매에 모두 나온다. 정보를 한 곳에 둘까?
- **오후**: 채집물을 상호작용하면 숲에서 사라지고 로그가 찍히게 만든다.
- **완료 기준**: 산초·약초·버섯 3종을 채집할 수 있다.

#### 11/12 목 · 가방 (F-05)
- **오전**: 가방에 넣기, 빼기, 가득 찼는지 확인하기를 만든다.
- **오후**: 채집과 연결한다. 가방이 가득 차면 채집이 막히고 알림(로그도 괜찮다)이 나온다.
- **완료 기준**: 용량만큼 채집되고, 그 이상은 채집되지 않는다.
- **생각해볼 질문**: 같은 산초 3개는 3칸일까, 1칸에 3개일까?

#### 11/13 금 · 숲 HUD (F-16) + 1주 점검
- **오전**: 화면에 가방 용량(예: 3/10)을 보여 준다. 기존 플레이어 UI 작업을 활용한다.
- **오후**: 밀린 작업 따라잡기. 남는 시간에는 1주를 돌아본다.
    - 계획보다 늦은 기능은 무엇이고, 왜 늦었나?
    - 2주차 계획에서 뺄 것이 있나?
- **완료 기준**: 채집하면 HUD 숫자가 **바로** 바뀐다.

### 2주차 — 하루 루프 완성

#### 11/16 월 · 낮 제한 (F-06) + 하루 루프 설계
- **오전**: 체력 또는 남은 시간을 만들고 HUD에 보여 준다. 다 떨어지면 로그를 찍는다.
- **오후**: 하루 루프 설계
    - 낮·저녁·밤·정산 4단계를 무엇으로 표현할까?
    - "지금이 무슨 단계인지" 알아야 하는 스크립트는 어떤 것들일까? 단계가 바뀌면 그 스크립트들은 어떻게 알게 될까?
- **완료 기준**: 낮 자원이 0이 되는 순간을 코드에서 잡아낼 수 있다.

#### 11/17 화 · 하루 루프 (F-07)
- **오전**: 단계 전환을 구현한다. 낮 → 저녁은 F-06으로 넘어가고, 나머지 단계는 버튼이나 키로 넘어간다.
- **오후**: 단계가 바뀔 때 장소(숲 ↔ 마을)가 바뀌는지 테스트한다. 씬을 나눌지, 한 씬에서 위치만 옮길지 정한다.
- **완료 기준**: 낮 → 저녁 → 밤 → 정산 → 다음 날 낮이 끊기지 않고 돈다(아직 기능은 비어 있어도 된다).

#### 11/18 수 · 가공 (F-08) + 마을 HUD
- **오전**: 레시피 1~2개만으로 가공을 만든다. 재료를 쓰면 완성품이 생기고, 재료가 모자라면 막힌다.
- **오후**: 마을 HUD를 만든다. 재고와 오늘 매출을 보여 준다.
- **완료 기준**: 낮에 캔 재료로 저녁에 요리 하나를 만들 수 있다.

#### 11/19 목 · 판매 (F-09) + 연결
- **오전**: 손님 1명, 주문 1개로 판매를 만든다. 맞는 물건을 주면 돈이 오른다.
- **오후**: 정산 화면에 오늘 번 돈을 보여 주고 다음 날로 넘어간다.
- **완료 기준**: 하루 한 바퀴가 처음부터 끝까지 이어진다.

#### 11/20 금 · 플레이 테스트 + 회고
- **오전**: 처음부터 3일치를 직접 플레이해 보고, 버그와 어색한 점을 목록으로 적는다.
- **오후**: 급한 버그부터 고친다. 마지막 1시간은 회고에 쓴다.
    - 잘 된 것 / 어려웠던 것 / 다음 2주에 할 것(P2 기능)
    - 명세서 "현재 구현 현황" 표를 고친다.
- **완료 기준**: 다른 사람에게 보여 줄 수 있는 플레이 영상이나 빌드가 있다.

## 일정이 밀릴 때

순서대로 줄인다. 위에 있는 것부터 먼저 줄인다.

1. HUD는 꾸미지 말고 글자만 보여 준다.
2. 레시피와 주문을 1개로 줄인다.
3. 숲과 마을을 한 씬에 두고 위치만 옮긴다.
4. 그래도 늦으면 판매(F-09)를 다음 2주로 넘기고, 낮 → 가공 → 다음 날까지만 완성한다.
